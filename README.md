# creem-nix

Nix flake for [Creem](https://creem.io)'s [`creem` CLI](https://docs.creem.io) (`@creem_io/cli`),
following the npm release feed.

The package installs the compiled CLI from the npm tarball (`dist/`, built with `tsc` upstream)
together with its runtime dependencies. Nothing is built from TypeScript here.

## Use

```
nix run github:mastratisi/creem-nix -- --version
```

In a flake-based NixOS config:

```nix
inputs.creem-nix.url = "github:mastratisi/creem-nix";
# ...
nixpkgs.overlays = [ creem-nix.overlays.default ];
environment.systemPackages = [ pkgs.creem-cli ];
```

Binary: `creem`. It reads its API key from `CREEM_API_KEY`, or from what `creem login` stores in
`~/.creem/`; a `creem_test_` key uses Creem's test environment.

## Known gaps

- The tarball has no lockfile. `package-lock.json` is generated by `update.sh` from the runtime
  dependencies and committed; `npmDepsHash` in `release.json` covers it.
- Only the x86_64-linux build has been run.

## How it stays current

- `update.sh` reads `https://registry.npmjs.org/@creem_io/cli/latest`, regenerates
  `package-lock.json`, and writes `release.json` (version, tarball URL, npm's SRI integrity hash,
  `npmDepsHash`). Needs `jq`, `curl`, `npm`, `prefetch-npm-deps` (all in `nix develop`).
- `.github/workflows/update.yml` runs it daily, builds, checks `creem --version` matches, commits
  `release.json` and `package-lock.json` if they changed, and tags the commit `v<version>`.
- `package.nix` only reads `release.json`; it has no version of its own.

Update by hand: `nix develop -c ./update.sh && nix build`.
